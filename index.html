MacOS+安卓平板环境下的副屏方案：低延迟有线投屏指南

在苹果生态中，iPad与Mac搭配使用随航（Sidecar）功能已非常成熟。但如果你的平板是安卓设备，官方方案缺失，需要自行配置。本文分享一个低延迟、高稳定的解决方案——通过有线USB连接实现AirPlay投屏，彻底规避无线网络延迟问题。

🛠️ 问题：无线投屏的延迟痛点

  • 传统AirPlay依赖Wi-Fi，常因网络波动导致200ms+延迟，影响办公/绘图体验。
  • 根本原因：AirPlay本质是局域网服务，无需Wi-Fi，有线连接（如USB）同样可行。

💡 网上找到的跨平台免费软件（如 Spacedesk、Deskreen）”，但这些方案普遍依赖Wi-Fi，延迟问题依然存在。

✅ 解决方案：有线AirPlay投屏（实测延迟<50ms）

通过USB网络共享+RNDIS驱动，将安卓平板转为Mac的”有线AirPlay设备”。步骤如下：

🔧 步骤 1：安卓平板设置

  1. 启用USB网络共享
  • 进入 设置 > 网络和互联网 > USB → 选择 USB网络共享（或”USB共享网络”）。
  • 注意：需确保平板已开启USB调试（开发者选项中），否则可能无法识别。
  1. 安装当贝投屏
  • 下载 当贝投屏（百度当贝市场下载）。
  • 关键：安装后不联网，直接使用USB共享功能。

🖥️ 步骤 2：MacOS设置

  1. 安装RNDIS驱动（根据芯片类型选择）：
  • Intel Mac（2015-2020机型）：
    HoRNDIS（官方推荐，安装后重启Mac）。
  • Apple Silicon (M1/M2/M3)：
    HoRNDIS-for-M1（专为ARM优化）。
  1. 连接设备
  • 用USB数据线将安卓平板连接到Mac。
  • 系统会自动识别为网络设备（无需额外配置）。

📱 步骤 3：启动投屏

  1. 在Mac上打开 系统设置 > 显示器。
  2. 选择 “扩展显示器”（非镜像模式）。
  3. 当贝投屏应用会自动检测到AirPlay设备（无需手动搜索）。
  4. 点击设备名称，即可将平板作为副屏使用。

💡 为什么有效？
USB网络共享创建了本地直连网络，RNDIS驱动让Mac识别安卓为网络接口，AirPlay流通过USB高速传输（理论速率480Mbps+），远超Wi-Fi的波动延迟。

⚙️ 优势总结

  1. 极低延迟：USB直连，延迟<50ms，适合绘图、视频编辑等对延迟敏感的场景。
  2. 无需网络：不依赖Wi-Fi，避免网络波动影响。
  3. 兼容所有安卓平板：只要支持USB网络共享功能。
  4. 成本为0：无需额外付费软件或硬件。
  5. 稳定可靠：实测1个月无中断，比AirScreen、Spacedesk等方案更稳定。

❗ 重要提示

  1. 当贝投屏版本：确保使用最新版（2023年后更新已支持AirPlay 2协议）。
  2. Mac驱动安装：
  • Intel版：下载HoRNDIS.pkg直接安装。
  • M1/M2版：按README操作（需允许系统扩展）。
  1. 首次连接：可能需等待5-10秒建立网络，成功后后续连接秒开。
  2. 替代方案：若当贝投屏不适用，可用AirServer（付费）+ AirPlay for Android（免费），但有线方案更稳定。

通过此方案，我已稳定使用安卓平板作为Mac副屏1个月，用于码代码、多屏办公，延迟几乎感知不到。告别无线卡顿，享受有线投屏的丝滑体验！
（测试设备：MacMini M4 + 不知名安卓平板（基于安卓8.0））

记录一下，rabbitmq重复消费问题

前段时间，在portainer看调试日志，发现一个问题，一个业务插入了两条数据。我滴个乖乖，这还得了，赶紧排查(dev环境_);

赶紧看代码，找业务逻辑，整体流程是：前端数据上传->入队->mq消费->入库；然后看入库部分的代码逻辑是没问题的；但是走了MQ，就考虑到了可能是重复消费了。

借此记录一下，关于重复消费问题以及我的解决办法。鄙人不擅长组织语言，经过一些资料查找(万能的百度)，总结了一下网络大神的专业解释：

1.生产者在发送消息给mq时，由于网络波动，可能导致生产者收不到mq的应答，这时候，生产者会再次发送消息。

2.同样的，mq在把消息给到消费者时，网络波动，mq没有收到消费者的应答，mq就会再次发送给消费者。

3.多消费者，如果未配置消费组，同样可能导致重复消费。

接下来说说我的解决方案，重复消费，最终导致的问题就是产生了重复数据，那何不再产生数据的时候，确定数据的唯一性。由于是大批量的数据，不可能用数据库的唯一约束来保证，那就从业务处入手。论一台机器什么读写最快？当然是内存，MQ终究是网络传输，速度能快得过内存？

说到内存，那就是首先选redis，利用redis设置一个唯一标识，作为锁，redis直接在消费开始时，判断是否锁已经存在，如果存在则跳过本次业务，否则上锁，业务处理完毕，释放锁。

hexo-admin新建文章报错：Error: Function yaml.safeLoad is removed in js-yaml 4

今天在写博客时，发现新建文章一直Loading，目测是报错了，打开日志一看果然，提示：Error: Function yaml.safeLoad is removed in js-yaml 4. Use yaml.load instead, which is now safe by default.

大概就是这么个意思：safeLoad这个函数在js-yaml4这个版本已经被移除了，使用load替代。

看懂了然后就好办了，根据错误日志： at getSettings (F:\imem-blog\node_modules\_hexo-admin@2.3.0@hexo-admin\api.js:44:26)

定位到报错行44行，发现使用的果然是yaml.safeLoad,把它修改成yaml.load，ok重启hexo，打开后台再次新建文章，搞定！

cnpm安装依赖报Error：Cannot find module fs/promises

出现这个错误，是由于cnpm版本跟node版本不匹配造成的，cnpm版本高了，node版本太低。

解决方案

1、升级nodejs版本，升级就不用说了吧，官网直接下载新版本的安装就行了。

2、降级cnpm版本，降级到7.1.0 npm install cnpm@7.1.0 -g 如果速度慢，加上 --registry=https://registry.npm.taobao.org

ok、搞定！

Java11的String.isBlank()

昨天，我一个同事让我给帮忙看个问题，下载了一个项目下来，eclipse一直报红，说是找不到方法，我看是一个字符串直接使用了isBlank()，再看了一下eclipse版本，photon….额，确实有点老了，compiler都不支持11，isBlank是11新增的一个方法，判断字符串的。

简单说一下解决，要么就是换版本，升级IDE的版本（eclipse 18以后的就可以），以支持java11编译（前提是你安装的JDK11+）；要么就是使用StringUtils替代，但是这种很不科学，一旦代码里面使用地方多的话，改起来就相当麻烦。

所以还是建议升级吧，都21年了。全面小康了。。。。。。咱工具也得与时俱进~
